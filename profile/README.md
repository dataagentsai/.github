# Clean Data Engineering

Open, free work on how production AI systems and data platforms are built and tested.
Everything here is open source (Apache 2.0). The website is **[cleandataengineering.ai](https://cleandataengineering.ai/)**.

## Test and build AI agents

| Repo | What it is |
|---|---|
| [agenttwin](https://github.com/dataagentsai/agenttwin) | Open-source AgentTwin: test any MCP agent in a simulated world, and judge it by what changed, not what it said |
| [reference-agent](https://github.com/dataagentsai/reference-agent) | A production-grade support agent with no framework, passing all four quality gates |
| [eval-harness-framework](https://github.com/dataagentsai/eval-harness-framework) | Mix any provider's evals, guardrails and cost rules in one run, with one result format |
| [agenttwin-lab](https://github.com/dataagentsai/agenttwin-lab) | An agent runs simulated days while an AI fixer repairs it, and can't mark its own homework |
| [claims-fnol-azure](https://github.com/dataagentsai/claims-fnol-azure) | A motor-insurance claims agent deployed on Azure, built to the specs |

## Open specifications

| Repo | What it is |
|---|---|
| [ai-assurance-catalog](https://github.com/dataagentsai/ai-assurance-catalog) | What must be **true** of an AI application before it's trusted: 118 test obligations |
| [ai-harness-catalog](https://github.com/dataagentsai/ai-harness-catalog) | What must **exist** around a model call: 16 harness layers |
| [clean-ai-engineering](https://github.com/dataagentsai/clean-ai-engineering) | The method: principles, spec formats and four quality gates |

## Review a data project

| Repo | What it is |
|---|---|
| [data-project-review](https://github.com/dataagentsai/data-project-review) | A Claude skill that reviews a data engineering project's documents and says what's missing at its stage, technical and delivery, with a fail-fast plan |
